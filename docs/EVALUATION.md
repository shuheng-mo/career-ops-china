# 评估体系

每个 JD 进来都会先过红线，再跑 A-F 六块评估，最后给出 10 维加权总分和推荐动作。所有规则都写在 `modes/` 下的 markdown 里，想改哪条直接跟 Claude 说。

---

## A-F 六块评估

| Block | 内容 | 配置位置 |
|---|---|---|
| **A 角色摘要** | Archetype、领域、职能、级别、业务方向、base 城市、TL;DR | `modes/_profile.md` |
| **B CV 匹配** | JD 每条要求对应到 `cv.md` 的哪一行；列出差距和弥补策略 | `modes/_profile.md` |
| **C 级别策略** | JD 暗示的级别 vs 你的实际级别；「不夸大地讲资深」和「被压级时怎么谈」两套话术 | 大厂职级对标表 |
| **D 薪酬与需求** | 看准网 / 脉脉 / OfferShow / 知乎 / 一亩三分地查薪资区间、口碑、真实工时、业务前景 | `modes/_shared.md` |
| **E 个性化方案** | 简历 Top 5 修改 + 脉脉 / LinkedIn 资料 Top 5 修改 | — |
| **F 面试准备** | 6–10 个 STAR+R 故事 + 主讲案例 + 红线问题预演（离职原因 / 加班 / 婚育） | `interview-prep/story-bank.md` |

`/career-ops story-sync` 会扫描所有 report 的 Block F，去重后按主题累积到 `interview-prep/story-bank.md`。

公司深度调研（`/career-ops deep`）的数据源改用脉脉职言区、天眼查、企查查、IT 桔子、36 氪、小红书。**不要用 Glassdoor / Levels.fyi / Blind 查中国公司。**

## 10 维评分

| 维度 | 权重 | 说明 |
|---|---|---|
| 北极星对齐 | 25% | 与目标 archetype 的契合度 |
| CV 匹配度 | 15% | 简历真实匹配 JD 的程度 |
| 级别 | 15% | JD 暗示级别 vs 你的实际级别 |
| **薪资（含工时折算）** | **15%**（上游 10%） | 国内薪资差异大 |
| 成长路径 | 10% | 团队是否扩张、技术方向是否前沿 |
| **工时与生活** | **10%**（上游 5%） | 大小周 / 996 直接影响生活质量 |
| **公司稳定性** | **10%**（上游 5%） | 国内裁员频繁 |
| 技术栈现代度 | 5% | |
| 流程速度 | 5% | |
| 文化信号 | 5% | 工程师文化 vs 官僚文化 |

去掉了上游的「远程质量」这一维：国内远程岗几乎不存在。

**低于 4.0/5 明确建议不投**，除非你给出具体理由要坚持。系统默认权重在 `modes/_shared.md` 和 `batch/batch-prompt.md`，个人权重写在 `modes/_profile.md`。

## Archetype（预置，仅作起点）

| Archetype | 主题 | 公司在买什么 |
|---|---|---|
| 数据工程师 | ETL/ELT、Spark/Flink、调度 | 把数据稳定汇进数仓的人 |
| 数据仓库 / 数据平台 | 分层建模、湖仓、Doris/StarRocks/ClickHouse | 从 0 到 1 或持续迭代企业级数仓的架构者 |
| 数据治理 | 元数据、血缘、质量、合规、主数据 | 让数据用得起、管得住、信得过的人 |
| 大模型应用工程师 | RAG、Agent、Prompt、向量检索、Eval | 把大模型落地到业务并保证质量的人 |
| AI Infra | vLLM/SGLang、训推、显存优化、GPU 调度 | 让大模型跑得快、稳、便宜的人 |
| 后端（数据 / AI 方向） | Java/Go/Python、高并发、中间件 | 业务后端扎实、能配合数据和 AI 团队 |
| 平台工程师 / 架构师 | 内部平台、MLOps、CI/CD、SRE | 把工程组织的地基打好的人 |
| 大数据算法 / 数据科学 | 推荐、风控、AB、特征工程 | 用数据驱动业务并落地模型的人 |

系统会根据 `cv.md` 自动判断 archetype；JD 对齐度高但不完全落在预置类型里，也会给出合理评估。

## 多方向 Track

同时找几个方向时（例如「AI 应用为主，另一个行业方向为辅」），在 `modes/_profile.md` 的 Track 表里定义每个方向：

- 每条评估都标注所属 Track，写进 tracker 的 `track` 列
- 每个 Track 可以指定自己的简历底稿（`cv-<track>.md`），缺失时回落到 `cv.md` 并在 report 里注明
- 漏斗、看板、投递脉搏按 Track 分开算，能看出哪个方向真的在转化，哪个只是在凑数量
- 可选的**证据闸门**：某方向缺关键证据时，评估结果记为 `Blocked` 而不是直接投。它不是终态，补齐证据后解除

## 简历：事实层与改写层

- `cv.md` 是**事实层**：雇主、日期、学历、数字只从这里来
- 各方向的 `cv-<track>.md` 是**改写层**：可以改措辞、改标题、调顺序、删减、调整侧重，但不能出现 `cv.md` 里没有的雇主、日期、学历或数字
- `npm run sync-check` 强制执行这条规则，发现新增事实时以非零码退出。生成 PDF 前先跑一遍。国内大厂会做背调，同一个人的两份简历对不上是最糟糕的失败方式
- 定制简历写成 `output/*.md`，再 `npm run cv -- output/<file>.md` 出 PDF。md 是可编辑的源文件，改个错字重新跑一遍就行

## 硬红线

在 `config/profile.yml` 里写下你不接受的情况，评估前直接判 SKIP：

```yaml
deal_breakers:
  - "某前雇主（任何 BU、任何子公司）"
  - "大小周"
  - "外包 / OD / 派遣"

strong_preferences_against:   # 强烈不偏好，但不是绝对红线
  - "..."
```

派遣是常见陷阱：JD 上写的是甲方名字，实际签的是人力公司的合同。把常见派遣公司名（人瑞、中智、FESCO、外企德科、万宝盛华、科锐国际等）写进 `deal_breakers`，评估时会对照发布主体和合同主体判断；再把「派遣」「外包」加进 `portals.yml` 的 `title_filter.negative`，scan 阶段就会把这类标题丢掉。scan 和评估都会先过红线，命中就不再浪费精力。

## 大厂职级对标

`modes/_shared.md` 里有阿里 P、字节、腾讯 T、美团 L 等职级的对照表，Block C 用它判断 JD 实际对应的级别，以及谈级别时的锚点。

## 国内求职的特殊提醒

评估或 onboarding 过程中遇到以下情况，系统会主动提醒：

| 情况 | 提醒 |
|---|---|
| 33 岁以上 | 互联网的 35 岁门槛真实存在。优先考虑独角兽、中小厂、外企；大厂社招对资深 P7+ 容忍度更高 |
| 空窗超过 3 个月 | 在国内 HR 眼里是负面信号，提前准备好解释 |
| 想投远程岗 | 国内远程岗几乎不存在，海外华人公司有，但门槛高 |
| 没有大厂背景 | 用真实项目和数据弥补 |
| 评估 996 公司 | Block D 写明真实工时，由你自己决定 |
| 想转大模型方向 | 端到端落地经验比「会调 LangChain」重要：让面试官看到 Eval、可观测性、成本控制、业务影响 |
| 简历里有外包经历 | 不要隐瞒，用项目而不是 title 吸引人 |
| HR 问婚育 / 年龄 / 加班 | 这些问题不合规但确实存在，系统会帮你准备得体的应对 |

## 核心规则

**永远不要**

1. 编造经历或指标
2. 替你提交申请（提交 / 发送按钮永远由你来点）
3. 在触达消息里写出手机号（简历 PDF 页眉例外，必须有）
4. 推荐低于市场水平的薪资
5. 不读 JD 就生成 PDF
6. 用官腔套话

**永远要**

1. 评估前先读 `cv.md`（和可选的 `article-digest.md`）
2. 识别 archetype 并调整叙事角度
3. 引用 CV 的具体内容
4. 用中文数据源查薪资和公司
5. 评估完写进 tracker
6. 默认中文输出（JD 是英文时除外），保留英文技术术语
