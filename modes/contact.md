# Mode: contact — 主动触达（Boss / 脉脉 / LinkedIn / 微信）

中国大陆主动触达和西方差异很大。**Boss 直聘** 是投递+触达一体的主渠道（直接和 HR 聊）；**脉脉** 是 warm outreach 主场（找 hiring manager / peer）；**LinkedIn** 适合外企/海外岗。

## 去 AI 味铁律（2026-11-23 起，移植自 ra-人话，所有触达文案强制过检）

历史教训：2026-06-04 起系统停止生成完整触达语，只给匹配点，因为 AI 写的消息一直有 AI 味、用户从未采用。本节规则生效后恢复生成完整草稿，但**每条消息发出前必须过下面的扫描清单**。规则自包含在此（batch worker / subagent 不依赖用户级 skill）。

### 硬禁清单（命中任意一条 → 重写该句）

| 类别 | 禁用模式 | 改法 |
|---|---|---|
| 首条堆数字/项目细节 | 「2000 条测试集精确匹配 92%，20 多个业务同事自助取数」出现在打招呼里 | 专业场面话：方向对位 + 内部评价高 + 落地成功。数字只活在简历和面试里（2026-11-23 用户原话：正常人不会给 HR 一一罗列项目细节） |
| 追发连连看 | 简历发出后紧跟 bullet 对位清单（「对位的几条：- NL2SQL…- 治理…」） | 口语化非结构化短段：「这个岗要求的 X 我刚好做过，也有 Y，总体能胜任」。移动端打字快不了，秒回结构化清单在时间上就不像真人 |
| 二元对比壳 | 「不是A，而是B」「不只是A，更是B」「与其A不如B」 | 直接说后半句承载的判断 |
| 伪洞察标记 | 「真正」「其实」「本质上」「核心在于」「更重要的是」 | 删掉提示词，从事实起句 |
| 冒号讲义腔 | 「我的结论是：」「原因是：」「重点是：」 | 改普通句子 |
| 教程式开头 | 「别急着X，先Y」「顺序别反了」 | 直接说具体问题或观察 |
| 空泛指代 | 「这件事」「这些东西」「几个方向」 | 换成确切名词：检索方案、评测集、上线流程 |
| 空泛比较 | 「更适合」「更自然」不带场景 | 说出具体用途 |
| 抽象施压/口号 | 「差距会被拉开」「时代分水岭」「能力飞轮」 | 换成看得见的成本或行为变化 |
| 隐喻收尾 | 用比喻盖住具体信息 | 直接给结果 |
| 简历粘贴风 | 消息里列学历/证书/技术栈清单 | 学历只在 JD 硬筛时一句话带过 |
| 对称排比 | 工整的「有X、有Y、有Z」三连 | 拆成自然长短句 |
| 八股收尾 | 「期待您的回复」「希望有机会交流」「贵司」 | 用具体请求收：发简历？约 15 分钟？ |

### 信息密度原则（比词句更深的 AI 味来源）

招聘聊天发生在**移动端**。判断一条消息像不像真人，先看信息密度和结构时机，再看措辞：

- **打招呼阶段的信息颗粒度 = 方向 + 评价**，不是「指标 + 明细」。场面话不是空话：说的每句（内部评价高、落地成功）要能被简历和后续对话兑现
- **结构化 = 机器行为**。真人在手机上打不出短时间高度结构化的长消息；bullet、编号、对齐表格全部留给 report
- **时序真实**：简历发出 → 追发是随手补一句的口语段，不是精心编排的第二波弹药
- ra-人话 的「具体、给数字」适用于**文章**（作者展示工作）；聊天触达相反——具体数字出现在聊天里就是简历粘贴风。同一个「具体」原则在两种载体上方向相反

### 真人语感规则

- **动词具体**：「测了」「跑了」「踩过」「砍掉」「上线了」，不用「主导」「深耕」「赋能」「拥有」
- **允许不工整**：真人消息有长短句、有省略、偶尔口语颗粒度；一条消息全部完美对称就是 AI 味
- **时态对齐**：做过的事用完成时（「我用了/我测了」），别把已落地的事写成「我会用」
- **保留不确定**：候选人对某技术栈的真实疑虑可以写（「K8s 我只在小规模上用过」），别全磨平
- **批量多样性**：一次生成 ≥3 条触达时，开头结构至少 3 种开法（从对方产品起句 / 从自己的坑起句 / 从行业事实起句），禁隐形模板
- 技术术语保留英文（Agent、RAG、Eval、MCP），不要硬翻

### 发前扫描（生成后逐条过，命中即重写）

首条里有具体数字或项目明细？/ 追发是 bullet 或编号列表？/ `不是…而是` / `不只是` / `不仅` / `真正` / `其实` / `本质上` / `更重要的是` / `核心在于` / 讲义冒号 / `别急着` / `更适合`（无场景）/ `期待` / `贵司` / 三连排比 / 结尾是比喻不是请求

### 生成工作流

1. 从 report Block B/F 取三桶素材：**事实**（数字、工具、指标）、**判断**（候选人怎么看这个岗）、**经验**（踩过的坑、取舍）
2. 删壳：platform 客套、自我介绍框架、价值升华、重复上一段的总结
3. 用短段重写；Boss ≤200 汉字按消息 1/2/3 框架拆
4. 过发前扫描，输出到 `outreach/` 文件，**匹配点+待澄清** 段保留（用户可能想自己改写）

## 落盘约定（重要）

**所有触达消息必须写入 `outreach/` 文件夹**，不要只输出到对话里。候选人要直接复制到 Boss/脉脉/微信，code block 方便一键复制。

**文件名：** `{报告编号}-{公司slug}-{渠道}-{日期}.md`
- 编号对齐 `reports/` 里对应的评估报告（让 outreach ↔ report 可互相追溯）
- 渠道：
  - `boss` — Boss 直聘对 HR 首条消息
  - `maimai` — 脉脉 warm outreach（找 hiring manager / peer 要内推）
  - `linkedin` — 外企/海外
  - `wechat` — 已加微信的跟进
  - `portal` — SPA 官方投递的自填话术（Mokahr / 飞书表单 / 企业 careers 的 "推荐理由 / 自我介绍 / 申请原因" 文本框）
  - `email` — V2EX / 知乎内推贴、邮箱直投的正文
- 示例：`outreach/026-topquant-boss-2026-04-15.md`

**文件结构模板：**
1. 头部元数据（日期 / 渠道 / 对应报告链接 / Score / 状态）
2. 渠道注意事项（Boss 500 字符限制、脉脉 5 行限制等）
3. 消息 1 / 2 / 3 — 每条包在 ` ```text ` code block 里方便复制
4. 投前准备清单（从 report F 段摘）
5. 发送记录表格（时间 / 消息 / HR 回复 / 备注）

发消息后，在发送记录表格里填时间和回复，不要额外开文件。

## 快捷语法：发送记录 → tracker 自动同步

**触发规则：** 在 outreach 文件 `## 发送记录` 表的 **"消息 1"** 这一行，**"时间"** 列填入 `YYYY-MM-DD` → 跑 `npm run sync-outreach` 会把对应 # 的状态从 `Evaluated` 自动改为 `Applied`，并在 notes 里加上 outreach 文件引用。写入走 `tools/tracker-backend.mjs`（bitable 后端下直接写 Bitable，之后跑 `npm run tracker:export` 刷新本地快照）。

**示例：**

```
| 时间       | 消息   | HR 回复 | 备注           |
| ---------- | ------ | ------- | -------------- |
| 2026-04-15 | 消息 1 | 待回复  | Boss 直聘已发 |  ← 时间填了 → 触发
|            | 消息 2 |         |                |
```

**何时跑：**
- 用户说「#XX 发了」/「投了」/「试一下同步」 → Claude 跑 `npm run sync-outreach`
- 也可以用户自己手动跑

**顺手建跟进提醒：** 每条 `Evaluated → Applied` 会同时建一个 **+3 天的跟进任务**（飞书 task）。
这是 2026-07 停摆的发生点 —— 18 条触达发出去之后三个月无人跟进，因为「3 天后跟进」只存在候选人脑子里。
`feishu.capabilities.task` 没开时提醒落到 `data/reminders.md`（降级但不丢）。详见 `modes/feishu.md`。

**脚本规则（`tools/sync-outreach-status.mjs`）：**
- 不降级（如果状态已是 Applied/Responded/Interview/Offer/Rejected/Discarded/SKIP/Blocked，不动）
- 幂等（重复跑不会重复改）
- HR 回复列**不自动解析**（自然语言太脆弱）。脚本只检测 HR 回复列非空，提示用户「可能要手动升 Responded/Interview」，由 Claude 询问后改

**HR 回复升级（手动路径）：**
- 用户在发送记录 HR 回复列填 "约一面"、"加微信了"、"拒了"
- 用户告诉 Claude：「#XX HR 回了」/「#XX 进面试了」
- Claude 根据 `templates/states.yml` aliases 调 `updateApplication(num, { status, notes })`
- **升到 `Interview` 时顺手建日程**：调 `tools/feishu/schedule.mjs` 的 `createInterviewEvent({num, company, role, start, description})`。
  `description` 吃 Markdown —— 把 JD 摘要 + 公司背调 + 提问清单直接塞进日程描述，手机上开会前十分钟就能看到。
  它会自动再挂一个「面试前 24h 过简历一致性」的任务。
  ⚠️ **不要 Edit `data/applications.md`** —— `backend: bitable` 下它是 `tracker:export` 生成的只读快照，改了会被下次 export 覆盖

## Boss 直聘触达（国内求职主渠道）

Boss 是"投递+聊天"一体，HR 在 Boss 上就能直接过简历，和脉脉/LinkedIn 的 cold outreach 逻辑不同。

**Boss 触达的坑：**
1. **对接的主要是 HR，不是 hiring manager**。开场 30 秒要让 HR 看到"学历 + 项目 + 精准对位"，她才会转给技术 leader
2. **首条消息限约 500 字符**（≈200 汉字），超过截断 → 分 2-3 条发
3. **量化/金融/部分敏感公司会挂马甲**（如宽德投资挂"飞龙医疗"）—— 不要点破，按 JD 内容回应
4. **外包 / OD / 派遣这类雇佣形式标签不主动解释**，按 CV 如实写即可
5. **HR 回"方便发简历吗"→ 立刻发简历 + 追加一条"JD 对位补充"作为弹药**，方便 HR 转给技术 leader

**3 条消息框架（严格按此结构生成）：**
- **消息 1** — 首条打招呼（≤200 汉字）：方向对位 + 专业场面话（内部评价高 / 落地成功 / 反馈不错），**不带具体数字和项目明细**；学历只在 JD 硬筛时一句话带过
- **消息 2** — HR 要简历后追发：口语化非结构化短段（「岗位要求的 X 我刚好做过…总体能胜任」），**禁 bullet 清单**；gap 用一句轻描淡写的诚实带过
- **消息 3** — 3-5 天没回的 follow-up（≤60 字）：给 HR 台阶下，筛出僵尸岗

**Boss 规则：**
- 不发电话/微信号（平台会风控 + 违反全局规则）
- 不用"您好我对贵司充满热情"这类官腔
- 必须有 1 个 JD 里的具体关键词做钩子
- 不用 emoji

## 1. 找 target

**脉脉路径（warm outreach 专用）：**
1. 在脉脉搜公司名，看在职员工
2. 找 hiring manager（团队负责人）和 recruiter（招聘 HR）
3. 找 2-3 个同岗位 peer（背景相似的人）

**LinkedIn 路径**（仅外企/海外岗）：
1. 用 WebSearch：`site:linkedin.com/in {公司} {岗位关键词}`
2. 找 hiring manager + recruiter + peers

**注意：永远不要写出对方的电话号码或微信号。**

## 2. 选主 target

选 **最受益于候选人加入** 的那个人 — 通常是 hiring manager（不是 HR）。HR 是过滤器，hiring manager 是决策者。

## 3. 生成消息

### 脉脉触达消息（中文）

脉脉支持长一点的私信。3 段框架：

**段 1（钩子，1-2 句）：** 关于他公司的具体事 — 最好是技术博客、开源项目、最近的 Talk、产品更新。**不要泛泛说"我对贵司很感兴趣"**。

**段 2（证据，2-3 句）：** 候选人最相关的可量化成就。例如："我在 X 公司主导过 Y 项目，把 Z 指标从 A 提到了 B"。

**段 3（提议，1 句）：** 低压力的请求 — "想请您 15 分钟聊聊，了解一下团队对 [话题] 的方向，方便加个微信吗？" 或 "如果方便，能帮我看看我的简历是否合适这个岗位吗？"

**示例（已过去 AI 味扫描，含信息密度检查）：**
> [姓名] 你好。你们 [产品名] 的 [具体功能] 我用过，[一句真实体验或踩的坑]。
>
> 我之前在华为做数据方向的 AI 平台，内部用得不错；后来自己创业做 AI 应用，主力产品就是 Agent 方向的，落地反馈挺好。你们团队在 [方向] 上做得比较深，想找机会聊聊。
>
> 方便的话 15 分钟电话？或者我先把简历发你看看。

**脉脉规则：**
- 不要超过 5 行
- 要有一个让对方能对上号的细节（产品行为、团队动向），但**不是自己的项目数字**
- 不要用 emoji（脉脉职场氛围偏正式）
- 过一遍本文件顶部的去 AI 味扫描清单

### LinkedIn 消息（英文，仅外企/海外岗）

LinkedIn connection request 限 300 字符。3 句话框架：
1. **Hook**：something specific about their company or current AI challenge (NOT generic)
2. **Proof**：candidate's biggest quantifiable achievement relevant to THIS role
3. **Ask**：a low-pressure 15-min chat

### 微信触达（已经有微信号的情况）

微信第一句就直奔主题，不要寒暄。

> [姓名] 您好，我是 [候选人]，[同事 / 朋友] 推荐认识。看到贵司在招 [岗位]，我目前的方向和这个岗位高度相关，想请教您几个问题，方便聊一下吗？

## 4. 准备 2-3 个备选 target

每个 target 写一句"为什么是好的 second choice"。

## 5. 触达后跟进策略

- 发出去 3-5 天没回 → 不要刷屏
- 一周后可以发一次 follow-up，提供新信息（如"刚发了一篇关于 X 的文章，可能对您团队有用"）
- 还没回 → 换 target，不要纠结
