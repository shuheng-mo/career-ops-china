# 职能包：技术岗（AI 应用 / 数据 / 后端 / 平台）

`config/profile.yml` 里 `evolve.function: tech` 时，`/career-ops evolve` 用本文件决定**挖什么**和**样本长什么样**。
方法论（账本、证据分级、版本）在 `modes/evolve.md`，与职能无关；要支持新职能，照本文件结构新建一份即可。

## 证据维度

面试官验证一条技术经历时，会依次追问下面这些。cv.md 里每个项目 / 工作段落，至少要在前 4 项上有 A/B 级证据。

| 维度 | 面试官的问题 | 账本里要有什么 |
|---|---|---|
| 个人贡献 | 「这里面哪些是你做的？」 | 角色、团队规模、你负责的模块 |
| 规模 | 「数据量 / 用户量 / QPS 多大？」 | 量级数字 + 统计口径 |
| 指标口径 | 「这个 85% 怎么算的？测试集多大？」 | 指标定义、样本量、测试集来源、对比基线 |
| 方案取舍 | 「为什么选 A 不选 B？」 | 考虑过的替代方案和放弃理由 |
| 落地状态 | 「上线了吗？谁在用？」 | 上线 / 内部试用 / demo，使用方和频率 |
| 问题与踩坑 | 「遇到最难的问题是什么？」 | 一个具体的失败或瓶颈，以及怎么定位的 |
| 前后对比 | 「优化前是多少？」 | 优化前后两个数字，以及测量方法 |

## 高风险 claim 信号（优先挖）

- 有百分比但没有样本量（「准确率 85%」）
- 「主导」「负责」但没有团队规模
- 延迟 / 性能数字没有说明测量环境
- 个人项目的指标来自 mock、stub 或很小的测试集——**必须在账本 `source` 写明**，否则面试被追问会出事
- 同一个数字在不同段落代表不同东西

## 参考样本

### 指标口径题

> 【指标名】是在【测试集来源，N 条】上测的，口径是【分子 / 分母的定义】。对比基线是【方案或模型】，它的结果是【X】。测试集【是否覆盖真实业务分布 / 有什么局限】。

### 个人贡献题

> 项目组【N】人，我负责【模块】，从【设计 / 编码 / 上线】全程跟进；【另一个模块】是【角色】做的，我参与了【评审 / 联调】。

### 前后对比题

> 优化前【指标】是【X】（在【环境】下用【方法】测的），我做了【改动 1、改动 2】，优化后是【Y】。其中贡献最大的是【改动】，因为【原因】。

### 落地状态题

> 目前【上线 / 内部试用 / 演示】，使用方是【团队或用户群】，【频率 / 调用量】。没上线的原因是【原因】。
